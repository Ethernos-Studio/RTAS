# EYESOFPRIESTESS 优化方案（2026-11-15 定稿）

> 目标：把"实时叠加层 + VLM 场景描述"从**能跑**推进到**敢用**。
> 本文只写"可执行的动作 + 验收指标 + 依赖"，不写愿景。

---

## 0. 现状（已实测，不再靠猜）

| 项目 | 当前值 | 测法 |
|---|---|---|
| 检测 mAP50（val=1-9，固定） | 0.700 | `radar val` |
| 检测 P/R（IoU 匹配） | 0.68 / 0.75 | `tools/eval_val.py` |
| 合并框（多怪合一） | 1280 下 6 个，抑制后 5 个 | `tools/merge_rate.py` |
| 身份 top-1（点击中心裁图） | 98.7% | `radar identity-check` |
| **身份 top-1（检测框裁图，线上真实）** | **44~51%** | `tools/check_gallery_repro.py` |
| 身份 top-1（多尺度融合） | 50.0%（无提升） | `tools/identity_multiscale.py` |
| 分辨率对检测的影响 | 可忽略（576p/1080p 都 recall 0.95） | `tools/scale_effect.py` |
| 分辨率对身份的影响 | 明显（576p 掉 3~5 个点） | `tools/constrained_identity.py` |
| 血条门控（干员过滤） | 真敌人误杀 0%，但只能确认 57% | `tools/check_bar_gate.py` |
| 图库覆盖 | **仅 16 类；1-9 的主力 O1 一条样本都没有** | `dataset/crops` 统计 |
| 录像有效分辨率 | ≈720p（1080p 是 OBS 插值） | `tools/estimate_native_res.py` |

### 结论（决定了后面所有优先级）

1. **检测够用**，问题不在检测；
2. **身份识别是最大短板**，且主因是**类别覆盖不全 + 裁图分布不匹配**，不是 embedding 结构；
3. **sim 不能当预言家**：不知道死没死，同路线还会超车（移速差、阻挡 1 漏过），
   但**出怪表 + 路线 + 种类集合**是确定的，可以当"候选约束"；
4. 朋友那套是**安卓内存**，PC 端不通用，不能直接搬。

## P0 数据与尺度归一化（预计 3~4 小时，我全包，你只需 15 分钟标注）

### P0.1 720p 归一化
- 录像有效分辨率≈720p，直播窗口 576p 原生 → 统一到 **1280×720** 训练/推理。
- 实现：`radar build --scale 0.667`（新增参数），SAM 仍在原图算框，落盘前缩放图与标签；
  `embed` 训练与图库裁图同样按 720p；直播侧把 576p 放大到 1280×720（已实现，改目标尺寸）。
- 验收：`radar val` 不掉点（允许 ±0.01），直播框置信度整体上移 ≥0.05。

### P0.2 负样本（治干员/立绘/召唤物误检）
- 已实现：`tools/live_capture.py` 抓帧 + `radar build --backgrounds`。
- 需要你：主界面抓 40 帧、部署阶段抓 40 帧（各 8 秒）。
- 验收：部署阶段误检框数量下降 ≥50%，且真敌人召回不掉（val 上 R 变化 ≤0.02）。

### P0.3 `operator` 类（已加，待标注）
- 类级标签，不需要覆盖 400 个干员；20~30 帧、每帧框住屏幕上的干员即可。
- 验收：干员类召回 ≥0.7、误报率 ≤0.1（人工看 20 帧）。

## P1 身份识别修复（预计 4~6 小时，我给工具，你补标）

这是**唯一能把线上 50% 拉起来的主线**，按性价比排序：

### P1.1 按关覆盖补标（最高性价比）
- 现状：图库 16 类，1-9 的主力 **O1 零样本**，直接导致该关上限只有 50%。
- 做法：`radar identity-coverage`（新增）列每关"标注里出现但图库没有/少于 N 张"的编号；
  你按它补标，每个缺口 20~30 个点。
- 验收：每关图鉴里每个编号样本 ≥30 张。

### P1.2 用"检测框分布"训练/建库
- 现状错配：训练用 SAM 紧框，线上是 YOLO 松框 → 差 5~10 个点。
- 做法：`embed-train --box-source det`（新增）用检测框裁图训练，并加**平移/缩放抖动**；
  图库重建也用检测框裁图。
- 验收：留出视频（1-9）身份 top-1 ≥ 70%。

### P1.3 跨帧投票
- 同一 track 连续 N 帧（8~12）的 embedding 取均值再匹配，抑制单帧噪声。
- 已实现单帧多尺度（无效），跨帧投票尚未做 → 预计 +10~15 点。
- 验收：留出视频 ≥ 80%。

### P1.4 置信度降级（必须要，避免"自信地错"）
- 规则：`score < 0.55` 或 top1-top2 差值 < 0.05 → 输出 `?` + 候选列表，
  而不是硬给一个错编号；叠加层用灰色框区分。
- 验收：错标率（给出编号且错）≤ 5%。

## P2 sim 约束（预计 3 小时，取决于关卡数据）

### P2.1 候选集合（不做时序假设）
- 从 `level_main_XX-XX.json` 取该关**全量出怪表**：
  每个时间窗内"可能存活"的敌人 = 出怪表按时间窗口切出的**多重集合**（允许超车、允许死亡）。
- 用途：把身份识别从"17 类里选"压到"3~5 类里选"（P1.4 的候选列表直接来自这里）。
- 验收：约束内 top-1 比全类高 ≥5 点。

### P2.2 路线归属
- 用单应把地图坐标投到屏幕；检测框按"离哪条路线最近"归组，
  只用来**生成候选**，不做顺序推断（超车已被用户证伪）。
- 验收：路线归属正确率 ≥80%（人工抽查 30 帧）。

### P2.3 时间轴对齐
- 三个信号：出怪时间表、左上角击杀数（`16/41`，OCR/模板匹配）、首次进画时刻；
  用击杀数做单调锚点，漂移 >2s 时重同步。
- 验收：对齐误差 ≤1.5s（用 1-9 的标注帧回放验证）。

---

## P3 PC 内存（单独立项，风险高）

- 朋友的方案是**安卓**；PC 端是另一套 IL2CPP 布局，偏移全不同，需要重新逆向。
- 风险：反作弊（TP/ACE 类）检测、封号、ToS 违约；**默认不做**，除非你明确要。
- 若做：优先级最高的是 `Enemy` 列表（id + 位置 + blocked_by），其次才是相机矩阵。
- 折中方案（低成本）：只读**无风险的替代信号**——击杀数、费用、部署倒计时，
  用 OCR 就够，不碰进程内存。

## 2. 验收看板（每次重训都要跑一遍）

```powershell
cd E:\RTAS\radar
uv run pytest tests -q                                   # 单测
uv run radar build --val-videos v002_1-9                 # 固定验证集
uv run radar train --epochs 40 --imgsz 1280 --workers 0  # 检测
uv run radar val --name latest                           # mAP
uv run python tools/eval_val.py                          # P/R/F1
uv run python tools/merge_rate.py                        # 合并框
uv run radar gallery-build --embedder weights/embedder.pt
uv run python tools/check_gallery_repro.py               # 线上真实身份准确率
```

| 阶段 | 指标 | 目标 |
|---|---|---|
| P0 | val mAP50 / 直播框置信度 | ≥0.70 / 均值 ≥0.65 |
| P0 | 部署阶段误检框 | 下降 ≥50% |
| P1 | 留出视频身份 top-1 | ≥80% |
| P1 | 错标率 | ≤5% |
| P2 | 候选集合内 top-1 | ≥85% |
| P2 | 时间轴误差 | ≤1.5s |
| 整体 | 直播叠加层"错标/漏检"人工抽检 100 框 | ≥90% 正确 |
